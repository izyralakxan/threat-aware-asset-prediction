Research methodology, in plain words

How the exposure forecast works

Every piece of software has weaknesses, and new ones are found every day. Attackers only use a few of them. This project teaches a computer to spot, early, which weaknesses attackers are likely to use next, and then shows which of an organisation's computers have them.

Think of a weather forecast

A forecaster studies years of past weather to learn which conditions come before a storm, then uses that to predict tomorrow. This project does the same with cyber attacks: it studies which weaknesses attackers used in the past, learns the warning signs, and forecasts which new weaknesses are likely to be attacked in the next 12 months.

Each step explained

  1. 1

    Collect public records

    Two free public lists are downloaded. The first lists every known software weakness. The second, kept by the US cyber agency CISA, lists the weaknesses that attackers have really used.

    Like collecting every weather report, plus a record of every real storm.

    382,538 known weaknesses · 1,721 really attacked
  2. 2

    Mark what happened next

    For each weakness, we look at the year after it became public and ask one question: did attackers start using it? If yes, it is marked as "attacked".

    This gives the computer examples with known answers to learn from.

    Only 390 of 127,580 were attacked within a year, about 3 in every 1,000
  3. 3

    Describe each weakness as it looked on day one

    Each weakness is described using only facts known on the day it was published: how serious it is, what kind of flaw it is, the words used to describe it, and whether that company's products were attacked before.

    No peeking at the future. Any detail added later, such as "this was attacked", is removed, so the computer cannot cheat.

  4. 4

    Teach the computer

    The computer is shown the weaknesses from 2021 to 2023, with their answers. It learns which signs tend to appear before an attack. Three different learning methods are tried and compared.

    Like a forecaster learning from past seasons before predicting the next one.

  5. 5

    Test it fairly

    The computer is adjusted using 2024, then given a final exam on 2025: weaknesses it has never seen. Its forecast is checked against what attackers actually did.

    Testing only on later years proves it can predict the future, not just remember the past.

  6. 6

    Check our own computers

    A scanning tool finds the organisation's computers and what software, and which version, each one runs. Each computer is matched to its weaknesses, and the forecast is combined with how important the computer is and whether it faces the internet.

    The result is a ranked list in a dashboard: which computers to fix first, and why.

How the fair test works

What the fair test showed

A security team cannot fix everything, so imagine it only has time to check the top 5% of new weaknesses. How many of the weaknesses later attacked would it catch?

44%caught using this project's forecast
16%caught using the usual severity score
5%caught by picking at random

The forecast is not perfect, and a small number of attacked weaknesses are still missed. But for the same amount of work, it finds almost three times as many of the dangerous ones as the usual approach.

Why every answer comes with reasons

For each forecast, the system shows what pushed the risk up or down, for example "this company's products are often attacked" or "the description says no password is needed". People can check the reasoning instead of trusting a number blindly.

Words you may hear

Weakness (CVE)
A known security flaw in a piece of software, with its own ID number.
KEV list
CISA's list of weaknesses confirmed to be used by real attackers.
Machine learning
A computer learning patterns from past examples instead of following fixed rules.
Severity score (CVSS)
The usual 0–10 rating of how bad a weakness could be, not how likely it is to be attacked.
Scanning (Nmap)
A tool that finds computers on a network and the software they run.
